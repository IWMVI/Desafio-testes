# BUG-001 — Menor não deve registrar receita

## Regra / contrato

**Menor de idade** não pode ter **receita**. Um **`POST /api/v1.0/Transacoes`** com **`tipo` de receita** e **`pessoaId`** de menor deve ser rejeitado **antes** da persistência (**400**), sem gravar a transação quando a regra é violada.

## Cobertura em testes

Integração — **`tests/api/MinhasFinancas.Tests.Integration/Controller/TransacoesControllerTests.cs`**

- **`Receita_para_menor_deve_retornar_bad_request`** — esperado **400 Bad Request** (não **201**, nem **500** por falha genérica).
- **`Receita_para_menor_nao_deve_ser_persistida`** — após o `POST`, não deve existir nova transação de **receita** associada ao menor (cobre aceite indevido ou persistência incorreta).

## Comportamento esperado

- **HTTP 400** (formato do corpo conforme política da API).
- **Persistência:** nenhuma nova linha de transação **receita** ligada ao menor do seed.

## Defeitos observáveis

- **201 Created** com registro criado — violação da regra.
- **500** em vez de **400** por regra de negócio — tratamento inadequado.

## Observações — Swagger / JSON

- **`tipo`:** **0** despesa · **1** receita. Este cenário exige **`tipo: 1`** no corpo.
- **`valor`:** o exemplo automático do Swagger pode trazer um número fora do intervalo de **`decimal`** (ex.: notação **1.79e+308**), gerando **400** em **`$.valor`** e falha de desserialização (*«The dto field is required»*). Substituir por um valor numérico válido (ex.: **100**).
- **Versão na URL:** usar o caminho gerado pelo Swagger (**`/api/v1/Transacoes`** ou **`/api/v1.0/Transacoes`**), conforme o seletor de versão da documentação.

**Pré-requisito:** ambiente **Development**, banco inicializado com seed (**`Pedro Oliveira`**, menor · **`Salário`**, categoria só receita — `SeedData.cs`).

## Como reproduzir (Swagger)

1. Abrir **`http://localhost:5000/swagger/index.html`** (ajustar porta/protocolo conforme `launchSettings`).
2. Selecionar a versão documentada da API (**v1.0** / prefixo exibido pelo Swagger).

### Obter GUIDs

3. **`GET /api/v1.0/Pessoas`** — **Try it out** — `page`: **1**, `pageSize`: **50** → filtrar **`nome`** **`Pedro Oliveira`** → **`id`** da pessoa.
4. **`GET /api/v1.0/Categorias`** — mesmo padrão → **`id`** da categoria **`Salário`**.

### POST a validar

5. **`POST /api/v1.0/Transacoes`** — **Try it out** — substituir os dois GUIDs no JSON:

```json
{
  "descricao": "Reprodução BUG-001 — receita para menor",
  "valor": 100,
  "tipo": 1,
  "categoriaId": "COLE_AQUI_ID_GUID_DA_CATEGORIA_SALARIO",
  "pessoaId": "COLE_AQUI_ID_GUID_PEDRO_OLIVEIRA",
  "data": "2026-05-07T15:00:00"
}
```

6. **Execute.** Indícios de BUG-001: **201**, **500**, ou receita persistida para o menor (**`GET /api/v1.0/Transacoes`** para conferência).

### (Opcional) Teste de integração

```powershell
dotnet test tests/api/MinhasFinancas.Tests.Integration/MinhasFinancas.Tests.Integration.csproj `
```

## Critério de resolução

Os dois testes de integração citados passam: resposta **400** no fluxo esperado, **sem** persistência de receita para o menor e **sem 500** neste cenário.
